# Decisions

Implementation choices the PRD leaves open, each with a one-line reason. Product decisions are in the PRD and are not reopened here.

## Stack and tooling

| Decision | Reason |
| --- | --- |
| Next.js 16.4.2 instead of the PRD's 15 | The sponsor asked for the latest stable release; 16 is current, and 15 is in backport-only maintenance. |
| Latest stable releases only, no betas, release candidates or canaries | Sponsor's call. Drizzle stays on 0.45.4 because 1.0 is still a release candidate. |
| A 3-day minimum release age for every package | Blocks a freshly hijacked release. It moved seven picks to their previous patch (stripe 23.0.0, zustand 5.0.15, jose 6.2.12, geist 1.8.1, lucide-react 1.59.0, @react-three/postprocessing 3.2.1, oxlint-tsgolint 7.0.2004); the audit confirmed none of the newer patches fixed a known vulnerability. |
| oxlint and oxfmt instead of ESLint and Prettier | `eslint-config-next` pulls in a high-severity `braces` advisory with no fix, and typescript-eslint does not support TypeScript 7 yet. oxlint has type-aware rules on TypeScript 7 and the Next.js, React and jsx-a11y rule sets. |
| `pnpm.overrides` forces drizzle-kit's legacy loader onto esbuild 0.28 | Removes GHSA-67mh-4wv8-2f99 from the dev toolchain; migrations still generate. |
| Postgres 18 with `uuidv7()` primary keys | Time-ordered ids index well and need no extension. |
| A local Stripe simulator (`PAYMENTS_MODE=sim`) beside the real Stripe adapter | This environment has no Stripe keys; the simulator signs webhooks with Stripe's own scheme, so the same handler code runs in both modes. |
| Rate limits stored in Postgres | Holds across serverless instances without adding Redis. |
| Own JSON logger instead of pino | One line per event with masking; avoids worker threads inside Next.js functions. |
| No `ics` package; the calendar file is generated by hand (RFC 5545, UTC times) | Twenty lines of code against one more dependency. |
| Fonts self-hosted from npm packages (geist, @fontsource/instrument-serif) | No runtime requests to font CDNs; the CSP stays `font-src 'self'`. |

## Data and booking

| Decision | Reason |
| --- | --- |
| Weekend pricing applies on Friday and Saturday (`weekendDays: [5, 6]`) | Matches how restaurants price weekend nights; it is a venue.json value. |
| Lunch uses the same tier fees as dinner until the owner changes them | The PRD gives one fee per tier and day type; each daypart is still a separate price rule. |
| Slot start times run from the daypart start up to, not including, its end (dinner 17:00 to 21:45) | "Slots inside dayparts", half-open like every other range in the system. |
| Bookings open 60 minutes ahead at the earliest and up to 60 days out | Venue.json values; stops same-minute bookings the kitchen cannot see. |
| Parties up to 6 can search; bookable tables seat at most 4 | Matches the PRD's turn times; larger parties see why no table fits and how to call. |
| The chef's counter is dining height (0.76 m), with chairs | Keeps the PRD's 1.15 m seat-view standard truthful at the counter. |
| Window two-tops seat guests north and south of the table; the main seat faces the water | Puts the view in front of the main seat, as the seat view promises. |
| Seat views use the 26 mm diagonal at every aspect ratio | Keeps the lens identical on portrait phones; never ultra-wide. |
| Guests are cookieless; a random device id in local storage is sent as a header | Works inside a third-party iframe, where Safari blocks cookies. |
| Booking refunds and cancellations by the venue are Owner-only; Hosts view, seat, mark no-shows and resend | Money movement stays with the owner role. The one exception is the PRD's automatic refund when a guest is seated at another table, which a Host triggers only on the booking's own day. |
| Magic links need a POST to redeem | Email scanners prefetch links; a GET must not use them up. |
| Holds and late re-confirmations take a per-table advisory lock, after the device lock | Concurrent inserts under the exclusion constraint can deadlock each other; one lock order per table turns that into a clean "taken". A deadlock (40P01) is also read as a lost race. |
| Seating is allowed on the booking's day only; a no-show only once its time has passed | A no-show keeps the fee, so marking one early would take a guest's money. The server refuses with `too_early`; Tonight shows later dates as "Booked" with no arrival actions. |
| The simulator emits `payment_intent.created` once per idempotency key | Matches Stripe, so retries never double-count in reconciliation. |
| Guests see the venue's name as the email sender, never ours | The booking is with the venue; the From name is sanitised against header injection. |

## Guest interface

| Decision | Reason |
| --- | --- |
| The mobile table card is our own non-modal sheet (`CardSheet`); vaul stays for the modal sheets | vaul's `modal={false}` still lets Radix hide the page from screen readers, which would leave the room unreachable while the card is open. |
| Swiping the card carousel jumps instantly when the selection changes elsewhere | An animated programmatic scroll passed through other cards and selected them on the way. |
| The reserve button reads "Reserve this table – $40" with an en dash | Reads as one phrase; the price is part of the button's name for screen readers. |
| Body text is 16 px; metadata lines (attributes, counts, prices, status pills) are 15 px and marked `data-meta` | The PRD rule, checked in the browser at every step of the a11y walk and on every portal screen. |
| Accessible names start with the visible text, extra context in `sr-only` | WCAG 2.5.3; voice-control users say what they see. |
| One rule orients the plan and the 3D camera: landscape faces the view side; portrait is the view bearing + 270° | Halcyon reads west-up and Orchard Room east-up on phones, with the water or garden on the same side in 2D and 3D. |

## Operator portal

| Decision | Reason |
| --- | --- |
| Tonight polls every 1.5 s while visible and pauses when hidden | Meets "a new booking appears within 2 s" without sockets; measured end to end in `tests/e2e/portal.spec.ts`. |
| Tonight plan badges carry just the booking time; labels fit compact-first (`labelFit`) | Neighbouring window tables must all show as paid on a tablet; the full form is used wherever it fits. |
| Table numbers are set in the interface sans inside serif names | The serif's "1" reads as "l" ("Table 11"). |
| Sign-in requests answer `{ ok: true }` for every address, with the lookup after the response | No account enumeration by answer or timing. |
| The sign-in link page uses a same-origin referrer policy | `no-referrer` made browsers send `Origin: null`, which the same-origin check rightly refuses. |
| Blackouts are entered in venue-local time and stored as UTC with `@date-fns/tz` | Correct across the clock changes; tested over the November change. |
| The widget flag cache is one per process (`globalThis`), 15 s | Next bundles pages and route handlers separately; per-module caches let the page and the APIs disagree. |

## The 3D room

| Decision | Reason |
| --- | --- |
| The 3D room is a separate chunk, fetched when the browser is idle after the 2D plan is interactive, and only where WebGL 2 works | Keeps the 2D budget (interactive in 2.5 s) independent of the 3D download; without WebGL the plan is the whole room. |
| The plan and the 3D room cross-fade once the scene has compiled its shaders, measured its labels and drawn 3 frames | No pop-in and no half-lit first frame. |
| Once 3D is up, the plan is `inert` and the 3D labels are the tables' buttons; before that, the 3D layer is `inert` | Each table is reachable exactly once by keyboard and screen reader, whichever renderer shows. |
| If the scene throws, an error boundary drops it and the plan stays | A GPU or driver fault never costs a guest the booking. |
| Sit here in 3D moves the camera to the seat and steps the card aside behind "Back to the room"; without 3D it shows the seat view full screen | The same promise in both renderers: you see what you will see from that seat. |
| The KTX2 transcoder is vendored under `public/vendor/basis`, unmodified from three 0.186.1 (Apache-2.0, license beside it) | Venue models with compressed textures load from our own origin under the CSP. |
| Frame loop on demand, device pixel ratio capped at 2, shadows rendered once | Battery and frame rate on mid-range phones; the room only changes when the camera or a table does. |
