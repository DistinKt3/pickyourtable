# Decisions

Implementation choices the PRD leaves open, each with a one-line reason. Product decisions are in the PRD and are not reopened here.

## Stack and tooling

| Decision | Reason |
| --- | --- |
| Next.js 16.4.2 instead of the PRD's 15 | The sponsor asked for the latest stable release; 16 is current, and 15 is in backport-only maintenance. |
| Latest stable releases only, no betas, release candidates or canaries | Sponsor's call. Drizzle stays on 0.45.4 because 1.0 is still a release candidate. |
| A 3-day minimum release age for every package | Blocks a freshly hijacked release. It moved seven picks to their previous patch (stripe 23.0.0, zustand 5.0.15, jose 6.2.12, geist 1.8.1, lucide-react 1.59.0, @react-three/postprocessing 3.2.1, oxlint-tsgolint 7.0.2004); the audit confirmed none of the newer patches fixed a known vulnerability. |
| oxlint and oxfmt instead of ESLint and Prettier | `eslint-config-next` pulls in a high-severity `braces` advisory with no fix, and typescript-eslint does not support TypeScript 7 yet. oxlint has type-aware rules on TypeScript 7 and the Next.js, React and jsx-a11y rule sets. |
| `pnpm.overrides` forces drizzle-kit's legacy loader onto esbuild 0.28 | Removes GHSA-67mh-4wv8-2f99 from the dev toolchain; migrations still generate. |
| Postgres 18 with `uuidv7()` primary keys | Time-ordered ids index well and need no extension. |
| A local Stripe simulator (`PAYMENTS_MODE=sim`) beside the real Stripe adapter | This environment has no Stripe keys; the simulator signs webhooks with Stripe's own scheme, so the same handler code runs in both modes. |
| Rate limits stored in Postgres | Holds across serverless instances without adding Redis. |
| Own JSON logger instead of pino | One line per event with masking; avoids worker threads inside Next.js functions. |
| No `ics` package; the calendar file is generated by hand (RFC 5545, UTC times) | Twenty lines of code against one more dependency. |
| Fonts self-hosted from npm packages (geist, @fontsource/instrument-serif) | No runtime requests to font CDNs; the CSP stays `font-src 'self'`. |

## Data and booking

| Decision | Reason |
| --- | --- |
| Weekend pricing applies on Friday and Saturday (`weekendDays: [5, 6]`) | Matches how restaurants price weekend nights; it is a venue.json value. |
| Lunch uses the same tier fees as dinner until the owner changes them | The PRD gives one fee per tier and day type; each daypart is still a separate price rule. |
| Slot start times run from the daypart start up to, not including, its end (dinner 17:00 to 21:45) | "Slots inside dayparts", half-open like every other range in the system. |
| Bookings open 60 minutes ahead at the earliest and up to 60 days out | Venue.json values; stops same-minute bookings the kitchen cannot see. |
| Parties up to 6 can search; bookable tables seat at most 4 | Matches the PRD's turn times; larger parties see why no table fits and how to call. |
| The chef's counter is dining height (0.76 m), with chairs | Keeps the PRD's 1.15 m seat-view standard truthful at the counter. |
| Window two-tops seat guests north and south of the table; the main seat faces the water | Puts the view in front of the main seat, as the seat view promises. |
| Seat views use the 26 mm diagonal at every aspect ratio | Keeps the lens identical on portrait phones; never ultra-wide. |
| Guests are cookieless; a random device id in local storage is sent as a header | Works inside a third-party iframe, where Safari blocks cookies. |
| Booking refunds and cancellations by the venue are Owner-only; Hosts view, seat, mark no-shows and resend | Money movement stays with the owner role. |
| Magic links need a POST to redeem | Email scanners prefetch links; a GET must not use them up. |
